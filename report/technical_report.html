Dr.DocBench Challenge 2026 · Document parsing track · Technical report

pranshu29 at Dr.DocBench 2026: Consensus Selection over Prompt-Diverse VLM Transcriptions for Expert-Level Document Parsing

Pranshu Rastogi and Rajneesh Tiwari, Independent Researchers · Team pranshu29 · Final rank 7 · Overall 84.54

Abstract

We describe a training-free system for the Dr.DocBench document-parsing challenge. A general vision-language model transcribes each page several times under different prompts, image settings and window sizes. A page-level minimum-Bayes-risk (MBR) selector, whose utility is the challenge's own text and reading-order matching, picks one transcription per page. A small set of rules derived from the evaluator's matching behaviour then refines it, and a word-level consensus layer corrects recognition slips that independent OCR engines confirm. Display formulas and tables are evaluated by best match, so we also emit LaTeX and HTML candidate blocks for each page. Our final submission scores 84.54 overall (Text_ED 0.1641, TEDS 71.86, CDM 81.84, Reading Order 85.65, rank 7). We report which choices transferred from the development set to the test set, where the remaining error sits, and a set of measured negative results, including five stronger commercial models that did not improve on the ensemble.

1. Introduction

Dr.DocBench selects book pages on which current parsers disagree, and its references follow annotator conventions that vary from book to book: which lines form one block, whether text inside a picture is transcribed, whether a list is a table, and where running headers and page numbers sit in the reading order. Our approach treats the problem as selection under uncertainty. Instead of training a parser, we generate many plausible transcriptions with one capable model and choose among them with the metric itself as the utility. All tuning used the development set (986 pages, 66 books) scored with a local copy of the official md2md scorer; the 509 test pages were used only through leaderboard submissions.

2. Task and evaluation

Each page is converted to Markdown. The scorer splits our page and the reference into blocks, matches text blocks by normalised edit distance, and reports four components. Text_ED and reading order are computed on matched text blocks; display formulas are scored by CDM and tables by TEDS, each against its best-matching prediction. The overall score is the mean of the components available on a page, averaged over pages. Reading the scorer closely gave three facts that shaped the system:

  • Consecutive predicted blocks are joined to one reference block only when that block is at most 300 normalised characters. Above that length a segmentation mismatch cannot be repaired by the matcher.
  • Our unmatched text blocks cost nothing while any reference block is unmatched, but once every reference block is matched they are joined into one record and counted in full.
  • Normalisation keeps only word characters (runs of four or more underscores become four), so punctuation and Markdown emphasis do not count, while capitalisation and digits do.

3. System

3.1 Transcription runs

The base model is a general vision-language model served through OpenRouter (Section 6). Pages are sent as two-page windows at 1600 px on the long side, temperature 0. The prompts evolved through several versions; the ones in the final pool add these conventions in turn:

  • v6: copy capitalisation exactly; never write placeholders for illegible text.
  • v7: write page furniture (running headers, footers, page numbers) after the body, in a labelled section, because the references place it last.
  • v10a / v10b / v11: read multi-column pages column by column and start a new paragraph at a column break; v10b also splits paragraphs interrupted by pictures; v11 draws PaddleOCR-VL layout frames on the image.

Further runs vary contrast preprocessing, image size (1200 px) and window size (one page). PaddleOCR-VL and the MinerU pipeline provide layout blocks, tables and formulas. The final candidate pool for selection has eight transcriptions per page: five base runs (three prompts, a contrast variant, PaddleOCR-VL) and the three column-break runs.

3.2 Page-level rules

Every candidate passes through the same deterministic rules, each kept only if a leave-one-out ablation on the development set showed it helping:

3.3 MBR selection

For each page we choose the candidate with the highest average agreement with the other runs, where agreement between two candidates is the official text and reading-order matching computed with one of them standing in as the reference. This replaces a character-level medoid and adds about one point on the development set. Adding the three column-break runs as candidates and the six column-break variants as extra pseudo-references raised development Text_ED from 0.1264 to 0.1168 and reading order from 87.79 to 88.58. On the leaderboard this change gave +0.60 overall (Text_ED −0.0048, reading order +0.74).

3.4 Word-level consensus

Inside each paragraph of the selected page, the other runs' versions are aligned word by word. A word changes only when a strict majority agrees, the new spelling is close to the old (an OCR slip, not a different word), the change is not capitalisation alone, and an engine outside our model family (PaddleOCR-VL or MinerU) has the new word and not the old one, or the old word is not a dictionary word. A plain majority vote lost 0.06 on development because our runs share one model and therefore share errors; the gated version is small but never hurt a page.

3.5 Formula and table candidate blocks

Display formulas and tables are evaluated by best match: each reference formula or table is paired with its closest predicted one, and predicted blocks that match nothing are ignored. Display formulas also take no part in text or reading-order matching. The references write many styled lines (italic captions, bold labels, stage directions) as display formulas such as $\textit{…}$. We therefore append to each page standalone LaTeX candidates: every line of the page in the wrapper styles the references use (\textit, \textbf, bold italic, \text, underlined), the same lines from the other candidate runs, and inline formulas of all runs written as display formulas. Tables are handled the same way, with alternative transcriptions (PaddleOCR-VL, crop-level transcriptions, other runs) included as additional HTML tables. These blocks do not change the page's text or its reading order; their effect on the formula score is traced in Table 2.

5. Analysis

5.1 What transferred from development to test

Changes that select among existing transcriptions transferred well: the column-break MBR kept 68% of its development gain overall, 94% for reading order and about 50% for text. Changes that touched most pages or encoded a development-book convention reversed on test: adding contrast-enhanced runs as extra votes (−0.84), replacing two-page with one-page transcriptions (−0.63), and paragraph splits inside list blocks, which helped development books and cost text on test.

5.2 Where the error is

We located test error by blanking groups of books and decoding the leaderboard change. Books whose subjects never appear in development and books on which our runs disagree most (240 pages) held 56% of the text error and most of the reading-order error, at Text_ED 0.20 and reading order 77–81, against 0.12–0.16 and 85–88 for the rest. On development, 40% of the remaining text error is text we write that the reference does not keep, and half of all text error sits on 8% of pages where the reference made a book-specific choice: picture text kept as an image, a directory kept as a table, crossword clues kept as one block, a page whose reference is only its page number. Our words on those pages are right; the choice is not visible in the image or in our runs.

6. Resources and disclosure

  • Base transcription model: an unnamed vision-language model offered free on OpenRouter during the challenge (stealth/space-bunny-alpha); it produced every transcription in the final pool.
  • OCR and layout: PaddleOCR-VL (layout blocks, tables, formulas) and the MinerU 2.7.6 pipeline (formulas, word evidence for the consensus layer).
  • Also in the final submission: OpenAI GPT-6.1 sol-pro transcriptions of 120 test pages, used only as a source of formula and table candidates (Section 3.5).
  • Models tested and not used in the final system: OpenAI GPT-6 sol-pro, Google Gemini 3.8 Flash, Moonshot Kimi K2.5 and K2.6, Xiaomi MiMo v2.6 Pro, GLM and DeepSeek vision models, through OpenRouter and Hugging Face Inference Providers.
  • Evaluation: the official scorer code, run locally on the development set; the system is training-free (no fine-tuning, no external annotated data, no manual edits to test output).
  • Leaderboard use: besides regular submissions, three diagnostic submissions blanked groups of test books to locate error (Section 5.2), and some submissions applied one change to a single group of books to measure it there.
  • Formula and table candidate blocks: described in Section 3.5.

7. Conclusion

A single capable model, prompted several ways and filtered by an MBR selector that uses the evaluation metric as its utility, outperformed every stronger model we tested on this benchmark. Selection-based changes transferred to the hidden test set; rules built on development-book conventions did not. The remaining gap to the leading teams is in segmentation and reading-order conventions that vary by book, which a future system could address with layout-aware models trained on the annotation conventions themselves.
